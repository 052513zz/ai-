# Init-Spec Skill 使用说明

## 功能
- 根据用户描述直接生成完整的项目规格文档
- 创建标准化的需求分析文档（requirement.md）
- 生成系统规格说明书（spec.md）
- 设计接口文档（api.md）
- 制定测试计划文档（test.md）

## 规则
1. **当用户提出项目相关问题时，直接输出标准 SPEC 文档**
2. 必须包含项目的核心功能需求
3. 需要明确系统架构和技术选型
4. 接口设计需遵循 RESTful 规范
5. 测试用例需覆盖主要业务场景
6. 输出格式统一使用 Markdown，结构清晰

## 触发条件
当用户提到以下关键词时，自动调用此技能并直接输出 SPEC：
- "创建需求文档"
- "写一个项目规格"
- "生成系统设计"
- "帮我设计一个" + [系统名称]
- "我需要一个" + [项目名称]

## 标准 SPEC 输出格式

### 1. 需求分析文档（Requirement）

```markdown
# 项目名称需求分析文档

## 1. 项目背景
[根据用户需求描述项目背景和目标]

## 2. 用户需求分析
### 2.1 用户角色
- [角色1]
- [角色2]

### 2.2 功能需求清单
| 序号 | 功能模块 | 功能描述 | 优先级 |
|------|----------|----------|--------|
| 1 | [模块1] | [描述] | 高 |
| 2 | [模块2] | [描述] | 中 |

## 3. 非功能需求
- **性能要求**: [描述]
- **安全要求**: [描述]
- **兼容性**: [描述]
```

### 2. 系统规格说明书（Spec）

```markdown
# 项目名称系统规格说明书

## 1. 系统架构设计
- **架构风格**: [单体/微服务/云原生]
- **技术栈**:
  - 前端: [框架]
  - 后端: [语言+框架]
  - 数据库: [数据库类型]
  - 中间件: [中间件]

## 2. 模块划分
| 模块名称 | 职责描述 | 接口数量 |
|----------|----------|----------|
| [模块1] | [描述] | [数量] |

## 3. 数据库设计
### 3.1 核心数据表
| 表名 | 用途 | 关键字段 |
|------|------|----------|
| [表名] | [用途] | [字段列表] |
```

### 3. 接口设计文档（API）

```markdown
# 项目名称接口设计文档

## 1. 通用规范
- **基础URL**: /api/v1
- **传输格式**: JSON
- **状态码**: 200成功 / 400参数错误 / 401未授权 / 500服务器错误

## 2. 接口列表

### 2.1 用户模块
| 接口 | 方法 | 描述 |
|------|------|------|
| /user/register | POST | 用户注册 |
| /user/login | POST | 用户登录 |

### 2.2 业务模块
| 接口 | 方法 | 描述 |
|------|------|------|
| /xxx/list | GET | 查询列表 |
| /xxx/create | POST | 创建资源 |
```

### 4. 测试计划文档（Test）

```markdown
# 项目名称测试计划文档

## 1. 测试环境
- **操作系统**: [系统]
- **数据库**: [版本]
- **测试工具**: [工具名称]

## 2. 测试用例设计

### 2.1 用户模块测试
| 用例ID | 测试功能 | 预期结果 |
|--------|----------|----------|
| U001 | 正常注册 | 注册成功 |
| U002 | 重复注册 | 提示已存在 |

## 3. 性能指标
- **响应时间**: ≤ 200ms
- **并发能力**: ≥ 100用户
- **准确率**: ≥ 99%
```

## 执行逻辑
1. **自动识别**：检测用户请求是否涉及项目设计
2. **直接生成**：无需追问，根据用户描述直接输出标准 SPEC
3. **结构化输出**：按照上述格式输出完整的规格文档
4. **可扩展性**：预留扩展点，便于后续补充

## 示例

**用户输入**: "帮我设计一个图书管理系统"

**输出**:
```markdown
# 图书管理系统需求分析文档

## 1. 项目背景
图书管理系统旨在帮助图书馆实现图书借阅、归还、查询等业务的数字化管理...

## 2. 用户需求分析

- 管理员：管理图书和用户
- 读者：借阅和归还图书

|------|----------|----------|--------|
| 1 | 图书管理 | 添加、编辑、删除图书信息 | 高 |
| 2 | 用户管理 | 用户注册、登录、信息管理 | 高 |
| 3 | 借阅管理 | 图书借阅、归还流程 | 高 |
| 4 | 查询功能 | 图书检索、借阅记录查询 | 中 |

## 3. 非功能需求
- 响应时间 ≤ 1秒
- 支持1000+并发用户
- 数据定期备份
...
```
