# 文档结构与提纲规范 (Structure Blueprint)

## 3.1 元结构原则
所有文档遵循"倒金字塔+模块化"原则：
- 顶部20%：核心结论/主旨全景（让读者30秒内抓住重点）
- 中部60%：分层论证/展开（每部分可独立阅读）
- 底部20%：总结升华/行动号召（回扣开头，形成闭环）

## 3.2 通用章节骨架
```text
[封面/标题区]
  └─ 标题公式：《JSP程序设计教程》学习心得——从理论到实践的Web开发之旅

[摘要/导语区]（占全文5-10%）
  └─ 三要素：背景（为何学JSP）+ 核心发现（学到了什么）+ 结构预告（怎么展开）

[主体论证区]（占全文60-70%）
  └─ 采用"MECE原则"：相互独立，完全穷尽
  └─ 每章遵循"论点→论据→论证→小结"四步循环

[边界/局限区]（占全文5%，可选）
  └─ 主动声明本文未覆盖的内容或存在的局限

[结论/行动区]（占全文10-15%）
  └─ 不引入新论据，仅整合前文并指向未来
```

## 3.3 题材定制模板：读书心得（约2000字）

### 模板B：读书心得
```text
1. 书籍与作者定位（一句话定义该书在知识谱系中的位置）
   - JSP在Web开发技术栈中的定位
   - 该书作为教材的特点

2. 核心论点梳理（作者的原意，非我的感想）
   - JSP技术的工作原理
   - JSP与Servlet的关系
   - 内置对象的分类与作用

3. 关键概念深读（选取2-3个核心概念，结合原文细读）
   - request与response对象
   - session与application对象
   - EL表达式与JSTL标签库

4. 个人经验勾连（具体场景，拒绝泛泛而谈）
   - 学习过程中遇到的困难与解决方法
   - 课程设计项目中的实际应用
   - 与Java Web其他技术的对比思考

5. 批判性思考（同意什么/质疑什么/补充什么）
   - 对该书内容组织的看法
   - 对JSP技术现状与发展的思考

6. 行动转化（这本书如何改变了我接下来的一个具体行为）
   - 后续学习计划
   - 技术深耕方向
```

## 3.4 段落微观结构
- **起承转合标记**：每段开头使用逻辑路标词（"具体而言"、"反观之"、"值得注意的是"）
- **信息密度**：每段不超过5个信息点，超过则拆分
- **过渡规则**：段与段之间必须有显性连接词或隐性逻辑链（禁止硬跳转）

## 3.5 长度控制公式
- 总字数 = 基础值 × 复杂度系数
  - 基础值：短篇(1500) / 中篇(3000) / 长篇(5000)
  - 复杂度系数：单一主题(1.0) / 对比分析(1.3) / 系统性综述(1.6)
  - 本文档目标：约2000字，复杂度系数1.0-1.2
